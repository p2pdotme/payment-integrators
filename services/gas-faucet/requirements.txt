# Fully pinned, including transitive dependencies. Regenerate with:
#
#   pip-compile --strip-extras -o requirements.txt requirements.in
#
# WHY THIS IS PINNED. This process holds FAUCET_PRIVATE_KEY and calls
# account.sign_transaction in the same interpreter. The Dockerfile runs
# `pip install -r requirements.txt` on every rebuild, so an unpinned list
# re-resolves against PyPI each deploy — a malicious release of eth-account, or
# of anything in its transitive tree, would execute next to the key with no
# code change, no review and no diff entry to notice. It is the one exposure
# here where the whole float goes rather than a capped slice of it.
#
# NOT hash-pinned yet. `--generate-hashes` needs every wheel for every platform
# and timed out against PyPI when this was generated. Exact pins stop a NEW
# malicious release, which is the vector above; hashes would additionally stop
# a compromised existing release being swapped in place. Worth adding.
